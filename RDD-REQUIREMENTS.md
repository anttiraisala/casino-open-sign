## Requirements
REQ-001 to REQ-011 describe the planned settings menu: it is NOT implemented yet and is not being implemented now.

| ID | Requirement | Acceptance criterion | Origin | Revisions |
|----|-------------|----------------------|--------|-----------|
| REQ-001 | Settings menu: a menu is a list of items; each item is either a submenu or a property. The user moves through it with the keys of REQ-005; how it is presented is a separate matter. Back returns to the place the user came from (the item that was selected when the submenu was entered); at the top level it leaves the menu. | A host test walks a sample menu tree: opening a submenu, going back lands on the same item, back at the top level leaves the menu. | Maintainer chat 2026-11-10 | |
| REQ-002 | A property has a name and a value. Types: integer (negative, positive or mixed ranges, e.g. -100..-10, -50..50, 0..255), float with linear scale, float with logarithmic scale, and choice (dropdown; a boolean is a choice of two). Each has min, max and default. A text (string) type is not needed yet. | For every type a host test shows the default is applied and the value never leaves [min, max]. | Maintainer chat 2026-11-10 | |
| REQ-003 | Step size: an integer property steps by 1 unless the definition gives another step. A float property divides min..max into 50 intervals unless the definition gives another step or number of steps. A logarithmic property needs min > 0 and multiplies by a constant ratio per step ((max/min)^(1/steps)). A shift button held while turning multiplies the step by 10 (capped to the range; a property may override the factor). | Host tests: integer 0..255 with default step moves by 1; float exponent 0.1..20 log gives 51 values with the default 2.67 on the grid; shift moves by ten times the step. | Maintainer chat 2026-11-10 |  2026-11-11: shift factor fixed to x10. |
| REQ-004 | Limits: with wrap off a step that would pass min or max stops exactly at that limit (both ends); with wrap on the remaining amount of the step continues from the other end (both directions). Wrap is set per property (default off). | Host tests with a stepped value near both ends, with wrap on and off, for integer, float and choice properties. | Maintainer chat 2026-11-10 | |
| REQ-005 | Keys: a free-running 16-position hex rotary switch changes the selection or value; three buttons: OK, BACK, SHIFT (the OK button, documentation name "OK-menu button", opens the menu from the status pages; its label in the UI and on the LCD is always `OK`). The menu rotary is relative (it moves the selection or changes the value by steps; it is the only hex switch). In the menu OK opens a submenu or starts editing a property. While editing, OK accepts the value and returns to the menu at that property; BACK cancels, restores the value the property had when editing started and returns to the menu at that property. In the menu BACK goes up one level. The list selection stops at both ends (no wrap). Turning the arrow or casino switch while the menu is open cancels any edit (value restored) and shows the status page. The menu always opens at the root; the inactivity timer runs only at the menu root while just browsing (no submenu, property view, edit or confirm page open): after 60 s without input the display returns to the status pages, the remaining seconds shown at the right edge of row 0; elsewhere there is no timeout. SHIFT held while turning multiplies the step by 10. | A scripted key sequence on the host (turn, OK, BACK, SHIFT) gives the expected value and menu position for each case above. | Maintainer chat 2026-11-10 |  2026-11-11: control set of the V2 sign (menu hex switch D42-D45, OK D48, BACK D49, SHIFT D50), timeout and no-wrap list. 2026-11-11 (OQ-006, OQ-007, OQ-011): OK-menu button name, relative menu rotary, timeout only at the root while browsing. 2026-11-12: program switch removed, so only the arrow and casino switches close the menu (IDEA-017). |
| REQ-006 | The menu is defined in a human-written JSON file with a `root` tree and a `common` section of reusable elements (properties, submenus, type templates). The same element may appear in many places; loops are forbidden and are detected by the tooling. A property field is taken from the built-in default, overridden by its type template, overridden by the property itself (e.g. integer step 1 unless set). | The tooling rejects a menu with a loop, accepts a shared element in two places, and a test shows a type template field being overridden by a property. | Maintainer chat 2026-11-10 | |
| REQ-007 | Row text: by default a property row shows its name and value; the maintainer can define any friendly text for a row (including the shown words for true and false). Quick-pick rows set a value directly with one OK press, with freely definable text (e.g. "Lights on" sets B to true; "Min brightness 10" sets an integer to 10). A row text longer than 16 characters scrolls (marquee) on the 16-character LCD row; it is not a build error. A property row whose name and value do not fit together in 16 characters scrolls as one text "Name: value": a pause at the start, one character per step, a pause with the last character at the right edge (2026-11-11). A turn at the first or last item changes nothing, and a move away and straight back within 300 ms keeps that row's scroll phase. | A sample menu has a property row with default text, one with custom text and two quick-pick rows; host tests show the displayed texts and that OK on a quick-pick row sets the value. | Maintainer chat 2026-11-10 | 2026-11-11: whole-row scroll "Name: value" for rows that do not fit (maintainer chat). |
| REQ-008 | Callbacks: a property may have no callback, one or several callback functions that are called when its value changes, in the order given; menu editing, quick-pick rows and bound controls all change values through the same path and call them the same way. | A host test: a property with two callbacks calls both in order on every change; a property without a callback just changes the value. | Maintainer chat 2026-11-10 | |
| REQ-009 | Values survive power-off (stored in EEPROM) and are applied at start-up. A value is written only when the user accepts it with OK (or by a quick-pick). Each property has its own slot (by order) and the stored data carries a layout tag; on a mismatch or invalid data all defaults are used (old values may be lost). | A host test with a mock EEPROM: set a value, restart, the same value is back; with empty or invalid stored data the defaults are used. | Maintainer chat 2026-11-10 |  2026-11-11: save only on OK, slot per property, layout tag. |
| REQ-010 | A property can be read-only (default false): the menu shows its value but does not let the user change it. A value shown in the menu updates immediately when it changes elsewhere (for example by a bound control). | Host tests: OK on a read-only row does not start editing; changing the value from outside changes the displayed text in the next loop pass. | Maintainer chat 2026-11-10 | 2026-11-11: OK on a read-only property opens a view page like the edit page (name; a padlock and the value on row 1), nothing can be changed, BACK or OK returns (maintainer chat). |
| REQ-011 | Hardware controls bound to properties (separate from the menu): a rotary switch and buttons can be bound directly to a property and change it through the same path as the menu (same limits, wrap and callbacks). A rotary switch can work in a relative way (turning steps the value) or an absolute way (the position sets the value). The property stays visible in the menu (read-only when wanted). | Host tests: a bound dial and a bound button each change a property with its callbacks called; a read-only bound property is shown in the menu and follows the control. | Maintainer chat 2026-11-10 | |
| REQ-012 | V2 controls: the arrow slide switch (D32) and the Casino open/closed slide switch (D30) each have a reverse flag (a boolean property stored in EEPROM, editable in the menu); the switch position itself is read-only in the menu. The speed switches SW3/SW4 and the mode button D33 are removed; the speeds are menu properties. | Host test: the reverse flag inverts the meaning of each switch; the removed pins are no longer read; speeds change only through properties. | Maintainer chat 2026-11-11 | |
| REQ-013 | V2 effects (replaces the program switch, which is removed: D34-D37 are free): the frame and the letters each have their own effect, chosen in the menu group Effects (Frame effect, Letters effect, Random delay); the two effect properties also open the Frame and Letters groups (one value, two places). Each effect property is 0..15 (no wrap, default 1, saved in EEPROM): 0 = Random, 1..15 = a fixed effect (letters: 1 Breathe .. 15 Marquee; each letters effect N goes with frame pattern N, some following the arrow direction). Value rows show the number first, e.g. `12 Slot machine`. Random: one shared timer, its length the property Random delay (integer minutes 0..30, default 2, step 1, no wrap; 0 = a random delay of 1..30 min drawn on every restart; the delay is stored, a drawn value is not). When the timer runs out only the groups set to 0 pick a new effect (each its own, never the same one twice in a row); a fixed effect never changes by itself; a group switched to 0 picks at once and restarts the shared timer. | Host tests: every fixed effect N starts letters pattern N and frame pattern N; a random group never repeats and uses all 15; only random groups change when the timer runs out; both random groups change at the same moment; delay 0 draws 1..30; delay N changes after N minutes; the saved effects load at power-up. | Maintainer chat 2026-11-11 | 2026-11-11: "read at boot" changed to "read all the time" (answer to OQ-013). 2026-11-12: program switch removed; effects moved into the menu (IDEA-017, maintainer: "Joo, poistetaan"); program 0..E / F random replaced by effects 1..15 / 0 random per group, shared random timer. |
| REQ-014 | V2 status page: row 0 `F12 L03 Open|Closed` (F = frame effect, L = letters effect, two digits each, at most 16 characters; a `*` before the number marks a random group and the number is the effect really showing now, e.g. `F*07`; `--` when unknown); row 1 shows the arrow as seen from behind the sign and the customer direction (arrow character + `Customer right|left`, 16 characters; `<-`/`->` fallback if the LCD ROM lacks the arrows). While the frame or the letters are random, row 1 alternates with `Change in M:SS` (about 3 s each). | Host test of the row texts for every combination of effects, casino state and arrow direction, and the countdown (shown when either group is random); an LCD check on the real display for the arrow characters. | Maintainer chat 2026-11-11 | 2026-11-12: row 0 changed from `#<hex> Casino Open|Closed` to `F12 L03 Open|Closed` and the countdown from program F to "a group is random" (IDEA-017, maintainer chose this row 0 on 2026-11-11). |
| REQ-015 | V2 menu content: Controls (arrow, casino read-only; arrow reverse, casino reverse), Effects (Frame effect, Letters effect, Random delay), Speed (three rows Frame speed, Letters speed, Arrow speed, float log 0.125..4, 30 steps, default 1 (exactly at step 18), 3 decimals, unit x; SHIFT moves 10 steps), a group per LED type, Frame (the frame strip), Letters and Arrow (the arrow sticks), each with its speed (Frame speed, Letters speed, Arrow speed; Frame and Letters start with their effect property) and Min (int 0..255 default 0), Max (int 0..255 default 80), Exponent (float log 0.1..20, 50 steps, default 2.67) and Mix (float linear 0..1, 50 steps, default 1.0; blends the linear and the logarithmic curve as in the brightness tool), Brightness (the same brightness properties again, grouped Frame / Letters / Arrow; each property exists once and appears in two places), and a preset Restore defaults (sets every property to its default after OK/BACK confirmation). | The generated menu tree matches this list; a host test walks every row and the Restore defaults preset sets all defaults in one EEPROM batch. | Maintainer chat 2026-11-11 |  2026-11-11: Letters brightness group and Mix property added (maintainer chat). 2026-11-11: Speed range changed from 0.25..4 / 24 steps to 0.125..4 / 30 steps, 3 decimals (maintainer chat); the EEPROM layout tag changes, so old saved values are dropped. 2026-11-11: Menu renamed and regrouped: Strip -> Frame, Stick -> Arrow; root now Controls, Speed, Frame, Letters, Arrow, Brightness, Random program, Restore defaults; speed rows named Frame speed / Letters speed / Arrow speed (maintainer chat). 2026-11-12: Controls loses program; new group Effects (Frame effect, Letters effect, Random delay; the effects also start the Frame and Letters groups); `Random program (Change delay)` replaced by Random delay in Effects; root now Controls, Effects, Speed, Frame, Letters, Arrow, Brightness, Restore defaults (IDEA-017). |
| REQ-016 | Quick-pick presets: a row may set up to 16 property values at once (hidden properties allowed, a value may be the word `default`); all values are applied first, then the callbacks run once and the EEPROM is written as one batch. A quick-pick that targets a read-only property gives a warning when the menu is generated, and the preset does not try to set that property. A destructive preset asks OK/BACK. No active-value marker is shown. | Host tests: a preset with three values calls each callback once and writes one batch; a read-only target gives a generator warning and is not set. | Maintainer chat 2026-11-11 | 2026-11-11 (OQ-012): build error changed to a warning. |
| REQ-017 | Menu editor tool: a browser tool (published as a link like the Plate Designer) edits the menu JSON of REQ-006 and shows a preview of the 2 x 16 character display and the key behaviour of REQ-005; it exports the JSON that a later generator turns into PROGMEM tables. The same core logic runs in the tool and in the host tests. | Node and browser tests: the sample V2 menu loads, validation reports loops and read-only quick-pick targets, preview rows are 16 characters, the exported JSON loads back unchanged. | Maintainer chat 2026-11-11 | |
| REQ-018 | Live preview while editing: while a property is being edited, every step of the rotary switch changes the value immediately and calls its callbacks, so the effect on the sign is seen at once (a brightness changes the light, a speed changes the animation, a lighting effect starts). OK accepts the value and ends the editing (the only moment it is written to EEPROM); BACK (cancel) restores the value the property had when editing started and calls the callbacks again, so the effect goes back too. | Host tests: while editing, each turn calls the callbacks with the new value and nothing is written to EEPROM; OK keeps the value and writes it once; BACK restores the start value, calls the callbacks with it and writes nothing; the same for the V2 sketch menu. | Maintainer chat 2026-11-11 | Behaviour already exists (REQ-005 accept/restore, REQ-008 callbacks on every change, REQ-009 save only on OK); this makes the live effect and the callback on cancel explicit. |
