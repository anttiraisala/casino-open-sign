# CLAUDE.md - rules and decisions for AI assistants

Chat with the owner in the language he writes (Finnish). Everything in this repository is English
(code, comments, docs, config, tests, file and branch names, commit messages). The only exceptions: `README-fi.txt`
files (Finnish translation of the README.txt next to them) and product names that contain Finnish characters.

## Working rules (from the owner)

- Do not implement or change anything until the owner asks ("toteuta", "toimi"). Questions, ideas and
  "explain in your own words" are discussion only; remind him at the end of the turn that nothing is implemented.
- Flag contradictions in a request before building.
- Hardware/Arduino work always comes with: `README.txt` and `README-fi.txt` containing exact wiring (component to pin)
  and a parts-to-buy list from partco.fi; an SVG electrical schematic in circuit-diagram style (symbols).
- Every wiring diagram and layout drawing is delivered as SVG and as PDF (same name). `python3 tools/export_pdf.py` creates the PDFs from the SVGs; run it after regenerating any SVG.
- Deliver project files together in ONE zip (the whole folder), sent as an attachment.
- Any test the AI asks the owner to run lives in its own sub-folder, self-contained (own layouts, wirings,
  `sketch.ino`, `diagram.json`, README and README-fi).
- Parts-list prices, stock and links are a snapshot (2026-11-02). Do not refresh them unless asked. Do not remind the owner about the snapshot or mention parts lists/prices any more; he asks for them separately when needed.
- After publishing (implement, commit, push) a program, end the final report by naming the program that was changed (demo program or main program, e.g. "Casino Open Sign V2"), so the owner does not run the wrong one.
- Sign of life rule for every Arduino sketch: the LED on pin 13 blinks while the program runs (shortly inverted on
  state changes, faster when many changes happen) and the Serial Monitor gets one line per second with changing values;
  the baud rate (115200) is stated at the top of the sketch, printed at start-up and written in the README. Skip the
  LED or serial output only if the project uses that pin or port for something else. Reference: `stick_test_direct/sketch.ino`.
  The sign sketch has it; `strip_test/` and `stick_test/` do not yet: add it when they are next updated.
- Arduino pitfalls: function signatures only with built-in types (automatic prototypes); NeoPixel objects must not be
  copied (named objects + a pointer array); non-blocking `millis()` timing.
- Host tests hard-code the expected values (not taken from the sketch constants) and are checked with mutation tests.

## Decisions

- Arrow design B (barbed head) with 10 Grove RGB LED sticks (the 11th shield connector A3 carries the CLOSED light, a white Grove stick behind the plate; D31 is free). Real stick size 83 x 10 mm, LED window 74 x 4 mm, 2 mm between sticks, rails on LED 3 and LED 8 of the bars, wings 30 degrees: the arrow is 349.76 x 102.32 mm. Single geometry source `tools/arrow_geometry.py`; drawings and drill template in `arrow_sticks/`. Stick names: L-CAP, L-WING-UP, L-WING-DN, RAIL-UP-L, RAIL-UP-R, RAIL-DN-L, RAIL-DN-R, R-CAP, R-WING-UP, R-WING-DN (connectors D2-D8, A0-A2). The sign sketch drives the arrow (phase 1, simple flow animation); the frame/letters/switch/button pins moved to D9/D10, D11, D32, D33; the CLOSED light is the 11th stick on A3; the old strip arrow is a backup in `backup/old_arrow_strips/`.
- Ball/dot rule: the black dot in layout/drill drawings is the BALL of the real stick (left half left, right half right, caps up; CLOSED stick unchanged). `STICK_BALL_AT_DIN_END` in the sketch (true/false) corrects the LED order; the Wokwi generator follows it. LCD status page shows the customer view, arrow symbol first ("<-Customer right"/"->Customer left"). Switch D32 handle = real arrow direction (reversible with `ARROW_POINTS_LEFT_WHEN_LOW`) (back view: GND contact on the right). Drill template is for the FRONT of the plate.
- Brightness curves: per LED type (strip, stick) a lookup table from min/max/exponent/mix/keepZero (`CURVE_DEFAULT_*`: min 0, max 80, exponent 2.67, mix 1.0, keepZero true; formula in the sketch), rebuilt by `setBrightnessCurve()`; hue-preserving `shapeColor()`. No global brightness: the curve max (default 80) is the limit. The phone tool `tools/brightness-tool/index.html` (artifact "LED brightness curve", same link) is republished and included in every zip; its defaults must equal the sketch defaults (`tests/brightness_tool_test.py`); no Excel. Menu + 4 encoders + 3 buttons + EEPROM UI is planned, not applied.
- Planned but not applied: 12 V WS2811 strips, 60 x 30 cm plate, versioned releases (current state = v1).
- Plate Designer: `tools/plate-designer/` (browser CAD tool for the front plate drill/cut layout; `index.html` + `app.js` + `plate-core.js` + generated `arrow-data.js`; README.md there). Plate 1-1000 x 1-1000 mm (default 600 x 300; defaults CASINO 30/10, OPEN 120/112, CLOSED 20/245, arrow 125/198 - they overlap, the stacked layout does not fit the plate; owner can arrange), shared hole diameter 5-30 mm (default 10), CLOSED = round hole and/or 74 x 4 mm slot, frame strip units of 100 mm = 3 LEDs, fonts stored by name only (Google Fonts fetched at runtime, not testable from the sandbox). Online at https://anttiraisala.github.io/casino-open-sign/ via GitHub Pages (branch master, folder /; root `index.html` redirects to `tools/plate-designer/`, `.nojekyll`; owner must switch Pages on, AI cannot: the gh proxy blocks it; repo visibility not checked). Also published as an artifact (slug f2576151-ab61-4c1b-b072-788b0609f3cd, built by `tools/build_plate_designer_single.py`; republish to the same link after changes). Mouse: right/middle button pans, left selects; left drag on empty space = rubber band over the texts (Shift adds, Ctrl/Cmd removes), Shift/Ctrl+click add/remove; a selected group moves and scales as one element (hole diameter constant), hole drag keeps the group; `S.sameHeight` (default on, checkbox under Height in CASINO/OPEN) keeps CASINO and OPEN equally high. Selecting a text (casino/open/closed) from the drawing flashes a gold frame (0.5 s) around its box and panel section (`flashText`); the panel scrolls only if the section is not fully visible (`core.scrollDelta`, 1/5 margins); no flash when already selected, none for the arrow. Changing the plate width/height resizes it around its centre (`core.resizePlate`: both edges move, content shifts by half the change). Plate centre: teal dash-dot centre lines + marker always drawn (`centreSvg`); boxes, holes and strip pieces snap to the plate centre lines (3 mm); holding Ctrl while dragging disables snapping. Several holes per letter: `texts.*.extraHoles` [{i,dx,dy}] (cell centre offsets, max 40), `cell.extras` from `placeText`, `core.suggestHole`; UI: add buttons per letter, double-click in a letter adds, double-click on an extra hole removes (own double-click detection in pointerdown, the SVG is rebuilt on every press). Options: `frame.inside` (checkbox under Plate in the side panel: LED strips on the plate, `core.frameSides`) and `export.plateCut` (plate edge as cut line in the letter cut EPS/DXF, DXF layer PLATE_CUT); no margin, no overlap warnings (owner decision). Strip pieces (100 x 10 mm) turn freely around their centre: `strips[{x,y,rot}]` with `stripsV: 2` ((x, y) = top-left of the UNROTATED piece, rot any angle 0-360 clockwise; older files with rot 0/90 are converted in `fromJson`), UI: Rotation field, round handle (Shift = 15 degrees), R = next 90 degrees; helpers `core.stripPoly/stripContains/stripSamples/stripHandle/stripAngleTo`. Frame material (`S.frameWidth` 0-100 mm, default 30; plate edge = frame inner edge, bars mitred 45 degrees, `core.frameBars`/`core.frameSheet`; independent of the LED strips): the panel shows perimeter/material, the frame page (A4 landscape, one scale) is the last page of the drill PDFs and `Frame PDF (A4)`. ## Requirement Driven Development (RDD)
- Files: RDD-REQUIREMENTS.md (overview and requirements), RDD-IDEAS.md (ideas and open questions), RDD-PROGRESS.md (status, action points, evidence), PROGRESS.md (dated change log).
- Keep all four current in every commit that changes the project.
- AI suggestions go to RDD-IDEAS.md first; requirements, the overview and out-of-scope lines change only after the maintainer accepts them.
- Do not implement until the maintainer explicitly says so (for example "toteuta"); say at the end of a turn when nothing was implemented.
- A requirement is "verified" only with evidence in RDD-PROGRESS.md.
